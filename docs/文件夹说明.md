# 文件夹说明

整理日期：2026-10-23。本文件夹按项目文件、环境配置和本机运行区分开管理。业务开发从仓库根目录各模块进入，环境操作统一从 `environment/` 进入。

## 给队员的项目文件

| 位置 | 用途 |
| --- | --- |
| `README.md` | 仓库与项目开发入口 |
| [项目目录与开发约定](项目目录与开发约定.md) | 项目结构、模块职责和后续开发约定 |
| [团队协作与接入](团队协作与接入.md) | 可直接发给队员的仓库、权限、版本及接入说明 |
| `pom.xml`、六个 `*-service/` | Java 17 聚合与服务目录骨架 |
| `rag-runtime/`、`frontend/` | Python 和 Vue 前端目录骨架 |
| `database/`、`deploy/`、`tests/` | 数据结构变更、部署和跨模块验证目录 |
| `docs/api/`、`docs/architecture/` | 共享接口与架构记录 |
| `.gitignore`、`.gitattributes`、`.editorconfig` | 本地文件排除规则、换行及缩进设置 |

上述文件通过 Git 分享即可。项目目录已建立，Java、Python RAG 和 Vue 业务功能尚未实现。

## 集中在 environment 的环境文件

| 位置 | 用途 |
| --- | --- |
| [environment/README.md](../environment/README.md) | 环境操作、版本、端口、数据位置与检查说明 |
| `environment/*.cmd` | 负责人日常启动、停止、检查和登录辅助入口 |
| `environment/校园RAG开发环境.code-workspace` | VS Code 工作区，仍以仓库根目录为开发目录 |
| `environment/*.ps1`、`environment/*.py` | 环境初始化、依赖安装、工具与模型准备、服务管理及验收 |
| `environment/docker-compose.yml`、`environment/elasticsearch/`、`environment/rocketmq/` | 开发中间件及附属配置 |
| `environment/requirements-*.in`、`requirements-*.lock.txt`、`model-env.example` | 统一依赖与无密钥模型参数 |
| [environment/docs/原始手册](../environment/docs/校园级RAG知识库平台环境安装与首次运行手册.pdf)、[SOURCES.md](../environment/SOURCES.md) | 原始安装手册与环境版本来源 |

上述脚本、模板和说明随 Git 分享。环境目录中的实际凭据除外，仍由每个成员在本机生成。`deploy/` 保留给业务部署，`tests/` 保留给业务验证，环境服务 Compose 与环境验收脚本只在 `environment/` 维护。

## 留在负责人本机的文件

| 位置 | 保留原因 |
| --- | --- |
| `.local/DockerDesktop/`、`.local/Python311/`、`.local/Ollama/`、`.local/GitHubCLI/` | 已安装工具，启动入口依赖它们 |
| `.local/docker-profile/`、`.local/docker-cli/`、`.local/docker-data/` | Docker 配置、登录相关状态及数据盘；本次均保留 |
| `.local/models/`、`.local/ollama-models/` | 已验证的嵌入、重排、生成模型 |
| `.venv/` | 已安装并验证的 Python 开发依赖 |
| `.setup/state/` | Ollama 进程标识、环境与快捷方式备份、安装来源记录 |
| `.setup/logs/` | 关键验收记录及正在写入的运行日志 |
| `environment/.env`、`environment/.env.application` | 本机随机凭据，与当前服务数据配套保管 |
| `.git/` | 仓库历史、分支和远端信息 |

`.local/`、`.venv/`、`.setup/` 继续位于仓库根目录，作为独立的本机运行区，不迁入 `environment/`，以保持已安装工具、虚拟环境、Docker 数据盘、模型与账号配置使用既有绝对路径。本机运行区和实际凭据已被 Git 排除，`.git/` 由 Git 自行管理。不要打包这些内容给队员；模型准备脚本需要时可重新生成下载缓存。

## 文件维护

公开仓库只分享项目源码、环境脚本、模板和说明。安装过程与目录迁移的历史记录保存在本机 `.setup/`，不作为队员接入步骤。

仓库已建立，不再保留仅用于首次创建私有仓库的 `Connect-GitHub.ps1`。日常克隆、个人账号登录、分支与 Pull Request 操作统一见[团队协作与接入](团队协作与接入.md)。已验证的运行入口、模型、虚拟环境、数据库数据、凭据和必要的目录占位文件继续保留。
