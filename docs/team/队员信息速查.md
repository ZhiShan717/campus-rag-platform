## 队员加入时需要做的事

1. 向负责人提供 **本人 GitHub 用户名、拟负责模块、电脑系统与内存、Docker 是否可用、是否需要本地模型**。个人分工尚未确定，需由团队确认。
2. 使用本人 GitHub 账号协作。负责人可按分工邀请队员成为仓库协作者；接受邀请后才有相应写入权限。没有写入权限也可通过个人 Fork 提交修改。
3. 先阅读完整队员手册的“队员本机准备”，按所负责模块安装工具。**克隆仓库不会带上工具、模型、数据库数据或虚拟环境。**
4. Windows 环境脚本首先适配负责人电脑，其中仍含负责人安装路径和 Docker 独立配置；在其他电脑运行前须按手册核对路径和 Docker 配置，不能直接将负责人一键启动入口当成通用安装器。

| 开发范围 | 当前约定 |
| --- | --- |
| Java | JDK 17，Maven 3.9.9；Spring 依赖组合待团队统一 |
| Python RAG | Python 3.11，独立 `.venv`，依赖按 [SDK 锁文件](../../environment/requirements-rag.lock.txt)安装 |
| 前端 | 计划 Vue 3 + Vite + TypeScript；负责人使用 Node.js 24.22.0 / npm 11.19.1，工程与包锁尚待初始化 |
| 基础服务 | Docker Desktop 的 Linux 容器；默认五项服务，消息队列按需启用 |
| 嵌入与重排 | `BAAI/bge-large-zh-v1.5`，向量 **1024 维**；`BAAI/bge-reranker-base` |
| 本地生成模型 | Ollama `qwen3:1.7b`，用于开发联调；统一 LLM/API 尚待确定 |

完成本机适配后，基础服务启动、检查和应用连接参数生成均从仓库根目录运行；具体顺序见完整手册。模型权重按需下载，不是所有队员都必须安装。

## 服务连接与共享方式

**当前没有团队共享开发服务器。** 下表 `127.0.0.1` 均指使用者自己的电脑，不能用这些地址连接负责人电脑；服务启动并检查通过后才可连接。不要将负责人电脑的地址或密码当作团队统一环境。

| 服务 | 每位成员本机的默认连接信息 |
| --- | --- |
| MySQL | `127.0.0.1:13306`；库 `campus_rag`，用户 `campus_dev` |
| Redis | `127.0.0.1:6379` |
| Elasticsearch + IK | `http://127.0.0.1:9200`；用户 `elastic` |
| MinIO | API `http://127.0.0.1:9000`；控制台 `http://127.0.0.1:9001` |
| Nacos | `http://127.0.0.1:8848/nacos`；用户 `nacos`，另使用 9848/9849 |
| RocketMQ（可选） | NameServer `127.0.0.1:9876`；Broker `127.0.0.1:10911`，另使用 10909/10912；启动脚本加 `-Messaging` |
| Ollama（按需） | `http://127.0.0.1:11434`；模型 `qwen3:1.7b` |

业务服务若在同一 Compose 网络内运行，应使用服务名和容器端口，例如 MySQL 使用 `mysql:3306`；上表是主机客户端连接方式。

**MySQL 共享规则：**每位成员使用自己的本地实例；通过 `database/mysql/migrations/` 共享建表及结构变更，通过 `database/mysql/seeds/` 共享可公开的开发样例。当前尚无业务表、迁移脚本或自动迁移流程，需团队实现后按统一方式执行。Elasticsearch 索引定义统一放在 `database/elasticsearch/index-templates/`，向量维度为 1024。无需共享负责人的数据库数据盘或管理员账号。

本机初始化会生成各自的随机凭据，分别保存在 `environment/.env`、`environment/.env.application`，均被 Git 排除。各成员保管自己的凭据；不要通过群聊、公开 Issue、截图或代码发送密码、令牌、LLM Key。负责人 GitHub/Docker 登录状态、`.local/`、`.venv/`、`.setup/` 和 Docker 数据盘不分发给队员。

如以后决定共用开发服务器，需另行确定服务器地址、独立服务账号、授权范围和维护人；届时再私下分发对应连接凭据。

## 开发位置与提交方式

| 工作内容 | 代码或资料位置 |
| --- | --- |
| Java 网关、认证、文档、检索、管理、评测 | `backend/gateway-service/`、`backend/auth-service/`、`backend/doc-service/`、`backend/search-service/`、`backend/admin-service/`、`backend/eval-service/` |
| Python 检索、重排、生成、编排、MCP 与评测 | `rag-runtime/` |
| 前端页面与 API 调用 | `frontend/` |
| 表结构、样例和索引定义 | `database/` |
| 接口契约、架构决策 | `docs/api/`、`docs/architecture/` |
| 环境脚本、依赖锁和开发中间件 | `environment/` |
| 业务部署与跨模块验证 | `deploy/`、`tests/` |

- 有原仓库写入权限：同步 `main` → 新建任务分支 → 提交与检查 → 推送任务分支 → 向原仓库 `main` 提交 Pull Request。
- 没有原仓库写入权限：个人 Fork → 同步原仓库 → 在个人任务分支开发 → 推送 Fork → 向原仓库 `main` 提交 Pull Request。
- 请负责人或相关队员审查后合并。上述为建议协作流程，尚未建立分支保护或持续集成规则；具体命令见完整队员手册。
- 接口、表结构、索引维度、依赖或环境变量变更时同步更新说明。公开仓库中的测试材料使用可公开的人工构造数据；安装包、缓存、模型权重和本机凭据不提交。
