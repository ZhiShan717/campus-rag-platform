# 项目目录与开发约定

更新日期：2026-10-23。项目采用一个仓库管理 Java 后端、Python RAG 和 Vue 前端；项目源码、团队资料、开发环境与本机运行数据分区维护。本文统一说明目录归属，取代原单独的“文件夹说明”。

```text

├── backend/                       Java 后端
│   ├── gateway-service/           网关、认证入口与路由
│   ├── auth-service/              用户、角色与权限
│   ├── doc-service/               文档、版本与处理任务
│   ├── search-service/            检索与 Java/Python 协作
│   ├── admin-service/             管理功能
│   └── eval-service/              评测任务与结果
├── frontend/                      Vue 页面、组件与 API 调用
├── rag-runtime/                   Python 检索、重排、生成、编排与 MCP
├── database/                      MySQL 迁移、开发样例与 ES 索引定义
├── deploy/                        业务 Docker、Nginx 与 Kubernetes 部署
├── tests/                         跨模块 integration、e2e 与 fixtures
├── docs/
│   ├── README.md                  文档导航
│   ├── team/                      队员速查与完整接入手册
│   ├── development/               本文：目录归属与开发约定
│   ├── api/                       接口契约
│   └── architecture/              架构决策
├── environment/                   开发环境配置、脚本与日常启动入口
│   ├── *.cmd                      启动、停止、检查与登录辅助入口
│   ├── *.ps1、*.py                依赖、服务与模型管理及验证
│   ├── docker-compose.yml         开发中间件
│   ├── elasticsearch/、rocketmq/  中间件附属配置
│   ├── requirements-*             Python SDK 与模型依赖锁
│   ├── model-env.example          无密钥模型参数
│   ├── docs/                      原始安装参考手册
│   └── 校园RAG开发环境.code-workspace
```

`.editorconfig`、`.gitattributes`、`.gitignore` 留在根目录，分别维护缩进、换行和提交排除规则；`.git/` 由 Git 管理。

`environment/` 维护开发环境，`deploy/` 维护业务应用部署；环境和模型检查留在 `environment/`，业务验证按模块范围放入模块自身测试目录或根 `tests/`。无需复制同一份配置到多个目录。

Git 不保存空目录，尚无实现的位置使用 `.gitkeep` 保留；新增真实文件后可以删除对应占位。当前仍为目录骨架，目录名称不代表功能已经实现。

## 本机私有区与分享边界

| 本机位置 | 保存内容与处理方式 |
| --- | --- |
| `.local/DockerDesktop/`、`.local/Python311/`、`.local/Ollama/`、`.local/GitHubCLI/` | 已安装工具，保持原路径 |
| `.local/docker-profile/`、`.local/docker-cli/`、`.local/docker-data/` | Docker 配置、授权状态及数据盘，不分发 |
| `.local/models/`、`.local/ollama-models/` | 模型权重，成员按需自行下载 |
| `.venv/` | 本机 Python 环境，成员自行创建 |
| `.setup/state/`、`.setup/logs/` | 运行状态、备份和检查记录，仅本机保留 |
| `environment/.env`、`environment/.env.application` | 随机凭据和连接参数，与相应数据卷配套保管 |

这些运行目录不迁入 `environment/`，以保持现有工具、虚拟环境、Docker 数据盘及模型使用既有绝对路径。它们已被 Git 排除，并在项目 VS Code 工作区中隐藏以减少干扰；隐藏不影响脚本访问，Windows 文件夹中的实际内容仍保留。

通过 Git 分享源码、环境脚本、模板、依赖锁和说明；不打包个人授权、本机运行区、安装包、数据卷、真实凭据或模型给队员。当前各成员使用独立本地数据库，通过版本化迁移和可公开样例共享结构与数据约定。

## Java、Python 与前端约定

根 POM 管理 Java 17 和 `backend/` 下六个模块，各子模块的父 POM 路径为 `../../pom.xml`。模块 `artifactId` 和 `cn.campus.rag` 包名前缀保持一致；Maven 标准源码结构见[后端导航](../../backend/README.md)。在仓库根目录的开发终端执行：

```powershell
mvn -o -B validate
mvn -o -B -pl backend/doc-service -am validate
```

该命令只校验模块结构。当前没有 Java 启动类与业务依赖，Spring Boot、Spring Cloud 与 Alibaba 版本须先统一，再写入 POM。不要沿用原始手册中尚未匹配的版本组合。

Python 使用根目录独立 `.venv` 和 `environment/` 的锁文件，[rag-runtime/requirements.txt](../../rag-runtime/requirements.txt)继续引用统一 SDK 依赖，不另维护一份版本。模型参数约定见 [model-env.example](../../environment/model-env.example)，BGE large 向量维度为 **1024**。

前端尚无 `package.json` 与应用入口，需先统一工具链并提交包锁文件，再按实际脚本安装、启动和构建。当前没有可用的业务启动命令。

## 协作与维护

按[队员接入手册](../team/团队协作与接入.md)准备环境；有写入权限者使用任务分支，无写入权限者通过个人 Fork 提交 Pull Request。接口、表结构、索引、依赖版本或环境变量发生变更时，同步维护对应说明，经审查后合并。

2026-10-23 整理后，原根目录六个 `*-service/` 统一位于 `backend/`；团队文档位于 `docs/team/`，开发约定位于 `docs/development/`，文档总入口为 [docs/README.md](../README.md)。`environment/` 启动入口和所有本机运行区位置保持一致；旧检查日志中的历史路径保留原样，不作为当前操作入口。
