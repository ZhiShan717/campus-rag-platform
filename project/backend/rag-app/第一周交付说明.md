## 一、这份代码是什么

一个能跑起来的 Spring Boot 后端，覆盖第一周要求的全部功能：

- 注册 / 登录 / JWT 鉴权 / 角色权限（USER、ADMIN）
- 制度（document）增删改查、废止、版本与生效日期管理
- 条款（clause）增删改查，自动生成 chunk_id
- 问答接口 `/api/qa/ask`：先筛现行有效条款 → 检索 → 用 chunkId 反查核验 → 拼出带出处的答案

技术栈：Java 17 + Spring Boot 3.2.5 + MyBatis-Plus 3.5.7 + JWT（jjwt 0.12.5）+ BCrypt。

## 二、怎么启动

数据库默认用 H2 内存库（本机没装 MySQL，这样零依赖就能跑）。

```bash
cd C:\Users\Asphalt\.codex\teaching\rag-demo
mvn -Dmaven.repo.local="C:/Users/Asphalt/.codex/teaching/.m2repo" \
    -Dspring-boot.run.jvmArguments="-Djava.io.tmpdir=C:/Users/Asphalt/.codex/teaching/tmp" \
    spring-boot:run
```

看到 `Started RagDemoApplication` 就是好了，服务在 `http://localhost:8080`。

想换成真 MySQL：改 `application.yml` 里的数据源，或启动时加 `--spring.profiles.active=mysql`，
再按 `application-mysql.yml` 里的地址填账号密码即可（建表脚本 `schema.sql` 是 MySQL 兼容语法）。

初始管理员：`admin / admin123`（启动时由 `DataInitializer` 自动创建）。

| POST | `/api/documents` | ADMIN | 新增制度 |
| PUT | `/api/documents/{id}` | ADMIN | 修改制度 |
| POST | `/api/documents/{id}/revoke` | ADMIN | 废止，可带 `replacedBy` |
| DELETE | `/api/documents/{id}` | ADMIN | 只删已废止且无条款的 |
| GET | `/api/clauses?documentId=` | 登录 | 某制度的条款 |
| POST | `/api/clauses` | ADMIN | 新增条款，自动生成 chunk_id |
| PUT | `/api/clauses/{id}` | ADMIN | 修改条款 |
| DELETE | `/api/clauses/{id}` | ADMIN | 删除条款 |
| POST | `/api/qa/ask` | 登录 | 问答，返回答案与引用 |

统一返回结构：

```json
{"code": 0, "message": "ok", "data": {}}
```

`code` 为 0 表示成功，其它为业务错误码（400 参数/业务、401 未登录、403 无权限、404 不存在、500 服务端错误）。

**注意**：HTTP 状态码统一是 200，错误信息在 body 的 `code` 里。前端判断成功与否看 `code`，不要只看 HTTP 状态。

## 五、验证过程中发现并修掉的 bug

**新增条款时报 `NULL not allowed for column CHUNK_ID`。**

原因：chunk_id 要用数据库自增 id 拼出来（`doc1-c1000`），但插入之前 id 还不存在。
原来的写法是「先插入 → 拿 id → 再回填」，而表结构里 chunk_id 是 `NOT NULL`，
第一次插入时它是空的，直接被约束拦下。

修法两处：

1. `schema.sql` 里 `chunk_id` 改为允许 NULL（注释写明了原因）
2. `ClauseService.create()` 加 `@Transactional`，保证「插入」和「回填」同生共死
