# 第一周：任务对照与学习笔记

依据：用户提供的七人课程对位版计划，第一周 2026/10/24—10/30。这里交付开发成果与复习材料，不将文件存在视为本人已学会、已观看课程或已完成团队评审。

## 10/24：环境与三个实体

交付：本机 MySQL 8.0.46、Workbench、Java 17、Maven 可用；`users / documents / chunks` 字段初稿已落实到字段字典和 V001。

课程：阶段1 27.2 MySQL 安装与配置、28.3 数据表操作。

要理解：数据库是表的容器；一行是一条记录；主键唯一标识一行。文档“制度族”和“某个版本”不同：document_key 标识制度族，documents.id 标识具体版本。条款必须关联具体版本，才能引用准确原文。

本人练习：在 Workbench 展开三张表，指出每张表主键；说明 chunkId=1022 为什么属于 documentId=102，而不是版本 103。

## 10/25：建表与字段字典

交付：`migrations/V001__initial.sql`、`字段字典.md`、`seeds/V001__demo.sql`。

课程：阶段1 28.3 数据表操作；阶段2 25.4 字段说明表。

要理解：BIGINT 对应 Java Long，DATE 对应 LocalDate，TEXT 存条款正文，VARCHAR 存有长度上限的标题和编号。版本不是小数，应存字符串；失效日允许 NULL，表示尚未设定结束时间，不等于“今天失效”。

本人练习：解释 NOT NULL 和空字符串的区别；找到检查空白标题的 CHECK。建表脚本只在空库执行一次，修改既有结构应新增迁移，而不是直接重复执行 CREATE TABLE。

## 10/26：唯一约束、关联和导入

交付：username 唯一、(document_key, version) 唯一、(document_id, chunk_no) 唯一；users→documents→chunks 外键；8 个版本、40 条条款。

课程：阶段1 31.1 约束、29.1 插入数据。

要理解：仅在注册前 SELECT 不足以防止并发重复注册，唯一索引才是数据库最后一道检查。FOREIGN KEY 保证关联目标存在，但不自动证明操作者有管理员权限。初始化账号是应用账号，数据库连接使用另外的 MySQL 账号。

本人练习：尝试新增重复的 demo_admin、将条款改挂到不存在的文档；预期分别出现重复键和外键错误。不要把真实密码填入 password_hash，应用层使用 BCrypt 后再保存。

## 10/27：CRUD 与 Mapper

交付：`02__crud_examples.sql`、三份实体、三个 Mapper；自动测试实际调用 BaseMapper 的新增、查询、修改、删除。

课程：阶段3 19.2 BaseMapper 通用 CRUD；阶段1 31.1 约束。

要理解：Entity 对应表，Mapper 执行 SQL；Controller 和 Service 负责 HTTP、权限、业务和事务。实体属性 documentId 映射到列 document_id。插入后自增 ID 回填到实体，不能自行使用列表序号做 ID。

本人练习：运行 CRUD 示例，观察中间 SELECT，再查询总数确认 ROLLBACK 后仍为 8 个版本和 40 条条款。修改 Mapper 测试中的标题，再运行测试。理解 updateById 默认忽略 null，显式清空字段需要 UpdateWrapper.set。

## 10/28：日期与版本关系

交付：version、status、effective_from、effective_to、replaced_by 及边界数据；`03__version_transaction.sql`。

课程：阶段1 28.2 数据类型详解、30.2 条件查询。

要理解：ACTIVE 表示已发布，不代表任意日期都有效。默认候选还要检查生效日和失效日。时间区间采用 `[effective_from, effective_to)`；先录入未来新版时，旧版继续有效到切换日。

本人练习：将有效候选 SQL 中 @as_of 依次改为 2026-10-29、10-30、10-31、11-01；预期制度 ID 集合依次为 `{102,104,106,107}`、`{102,104,107}`、`{102,104,107}`、`{103,104,107}`。说明为什么不能加 `replaced_by IS NULL`。

## 10/29：候选联查与索引

交付：`01__effective_candidates.sql`、`04__integrity_and_indexes.sql`、`DocumentMapper.selectEffectiveCandidates`。

课程：阶段1 31.3 多表查询；阶段3 22.2 索引创建原则。

要理解：先按文档版本有效性筛选，再 JOIN 条款得到 Python 候选。候选必须携带真实 chunkId、documentId、标题、版本、条款位置和原文。SQL 先提供有效候选；关键词匹配和排序属于 Python 负责人，不在这里假装实现。

本人练习：执行 EXPLAIN，找到 documents 与 chunks 的连接列；解释为什么 chunks 的联合唯一索引以 document_id 开头后，通常无需再建同列单独索引。小数据量全表扫描不代表索引失效，不能据此声称性能改善。

## 10/30：从空库重建、约束复查与快照

交付：`Test-Week1.ps1`、`Manage-Week1Database.ps1`、`snapshots/week1-demo.sql` 和验收报告。

课程：阶段3 12.6 数据库初始化脚本；阶段1 31.1 约束。

要理解：迁移脚本描述结构，种子脚本描述初始演示数据，mysqldump 快照记录某次实际数据库状态。备份“生成了文件”和“在新库恢复后逐列一致”是两个不同验收层次。数据库备份快照也不同于第二周历史问答的引用内容快照。

本人练习：运行自动验收，阅读 13 项测试结果；使用日常恢复脚本把快照恢复到新库，再执行候选查询。禁止对已有业务库直接重复导入或先删库再导入。
