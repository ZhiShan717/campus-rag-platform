## 一、注册异常检查（10.26）

检查对象：`POST /api/auth/register`。期望：非法输入一律 4xx 且给出明确提示；合法输入落库，密码非明文。

| 编号 | 用例 | 输入 | 期望 | 实际 | 结论 |
| --- | --- | --- | --- | --- | --- |
| R01 | 用户名为空 | `username=""` | 400，提示「用户名不能为空」 | | |
| R02 | 用户名全是空格 | `username="   "` | 400（服务端先 trim） | | |
| R03 | 密码为空 | `password=""` | 400 | | |
| R04 | 密码过短 | `password="123"` | 400，提示最少位数 | | |
| R05 | 用户名重复 | 已存在 `daiyue` 再注册一次 | 409，提示「用户名已存在」 | | |
| R06 | 大小写重复 | 已存在 `DaiYue`，再注册 `daiyue` | 409（唯一约束不区分大小写） | | |
| R07 | 超长输入 | 用户名 200 字符 | 400，不得写入超长数据 | | |
| R08 | 特殊字符 | `username="' OR 1=1 --"` | 400 或正常建号，但绝不可 500 | | |
| R09 | 前后空格 | `username=" daiyue "` | 存储为 `daiyue` | | |
| R10 | 越权字段 | 请求体带 `role="ADMIN"` | 忽略该字段，落库为普通用户 | | |
| R11 | 明文密码检查 | 注册后查库 `SELECT password FROM users` | 值为哈希串，不是原文 | | |
| R12 | 重复提交 | 连续两次相同请求 | 第二次 409，不产生两条记录 | | |

判定：R01—R06、R10—R12 全部通过才算注册合格；R07—R09 允许有一定宽松度，但不能 500。

## 二、权限检查（10.27）

三种身份：未登录、普通用户、管理员。`200` 表示接口正常返回，`401` 未认证，`403` 已认证但无权限。

| 接口 | 未登录 | 普通用户 | 管理员 | 备注 |
| --- | --- | --- | --- | --- |
| POST /api/auth/register | 200 | 200 | 200 | 注册默认普通用户，不开放管理员自选 |
| POST /api/auth/login | 200 | 200 | 200 | 失败统一提示「用户名或密码错误」 |
| GET /api/documents | 401 | 200 | 200 | 列表允许登录后查看 |
| GET /api/documents/{id} | 401 | 200 | 200 | |
| POST /api/documents | 401 | **403** | 200 | 新增制度仅管理员 |
| PUT /api/documents/{id} | 401 | **403** | 200 | 修改仅管理员 |
| DELETE /api/documents/{id} | 401 | **403** | 200 | 建议改为废止而非物理删除 |
| POST /api/qa/ask | 401 | 200 | 200 | 问答全员可用 |
| GET /api/history | 401 | 200 | 200 | **只能看到自己的记录**，换账号验证 |
| GET /api/admin/feedback | 401 | **403** | 200 | 管理端反馈列表 |

必查的三条越权场景：

1. 普通用户直接调 `POST /api/documents`，必须 403，且数据库无新增记录；
2. 普通用户改 URL 里的 `historyId` 查别人的历史，必须 403 或返回空，不能返回他人内容；
3. 未登录访问任意业务接口，必须 401 而不是 500。

## 三、新增保存测试（10.27）

| 编号 | 用例 | 操作 | 期望 | 实际 | 结论 |
| --- | --- | --- | --- | --- | --- |
| S01 | 正常新增 | 管理员新增一份制度 + 2 条条款 | 200，列表与详情都能查到 | | |
| S02 | 必填缺失 | 不填标题直接保存 | 400，指明缺哪个字段 | | |
| S03 | 条款为空 | 制度保存但一条条款都不填 | 400 或允许但详情提示「暂无条款」（需先定策略） | | |
| S04 | 生效日晚于失效日 | effective 2026-09-01、expiry 2026-08-01 | 400，日期规则校验 | | |
| S05 | 重复文号 | 保存已存在的 doc_no | 409 或允许（需先定策略），不能静默重复 | | |
| S06 | 刷新后仍在 | 保存后刷新列表 | 数据仍在，不是前端假数据 | | |
| S07 | 编辑生效 | 修改条款正文后保存 | 详情与引用同步更新 | | |
| S08 | 事务一致性 | 保存制度时故意让第 2 条条款报错 | 制度也不入库（事务回滚） | | |

S08 是这组里最容易被跳过的一条，也是最容易在演示时翻车的：制度和条款必须同事务提交。
