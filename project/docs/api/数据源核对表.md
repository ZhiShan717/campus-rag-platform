# 数据源核对表（10.26）

更新日期：2026-10-26　维护：戴月
用途：前端每一处显示的文字，都能对应到数据库里的一个字段。对不上的，要么改前端，要么补数据，不能"看着像"就上线。

## 一、核对范围

本次只核对与奖助学金制度直接相关的四类页面：制度列表、制度详情、引用卡片、问答页状态提示。用户中心、管理端统计暂不在内。

## 二、逐项核对

| 前端位置 | 显示内容 | 来源表.字段 | 取值口径 | 核对结果 | 风险 / 注意 |
| --- | --- | --- | --- | --- | --- |
| 制度列表 · 首列 | 制度名称 | documents.title | 全称，不带书名号 | 已对齐 | 名称过长需截断，悬停显示全称 |
| 制度列表 · 文号列 | 文号 | documents.doc_no | 原样输出 | 已对齐 | 演示数据带「〔演示〕」前缀，**不得在前端隐藏**，否则会被当成真实文件 |
| 制度列表 · 状态列 | 状态标签 | document_versions.status（当前 ACTIVE 版本） | 四值映射：现行有效 / 已被替代 / 已废止 / 未生效 | 已对齐 | 一份制度没有 ACTIVE 版本时显示「无现行版本」，不能留空 |

| 问答页 · 出错提示 | 错误信息 | HTTP 状态码 | 500/503 统一提示「服务暂不可用」 | 待接口确认 | 与「无依据」必须可区分 |

## 三、三处需要与前端、Java 对齐的口径

1. **mode 字段取值**。建议固定三个值：`CLAUSE_RETRIEVAL`（条款检索）、`RAG_ANSWER`（模型生成）、`NO_EVIDENCE`（无依据）。前端按值切换标签，不要在文案里做字符串包含判断。
2. **无依据与失败的文案**。
   - 无依据：「当前知识库未收录与该问题相关的制度条款」；
   - 服务异常：「检索服务暂不可用，请稍后重试」。
   两句话必须不同，验收时按这两句判定。
3. **状态标签的中文映射**。四个枚举值 ↔ 四个中文标签，映射表放在前端常量里，不允许后端直接返回中文。

## 四、核对结论

- 数据侧 12 个展示点，9 个已对齐，3 个等接口字段确认后复核。
- **没有出现"前端要显示、数据库里没有"的情况**，说明字段表覆盖了当前页面需求。
- 需要前端注意的一条硬约束：文号里的「〔演示〕」不能隐藏，状态列不能省略——这两处直接关系到演示的合规说明。
