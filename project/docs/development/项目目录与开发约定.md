# 项目目录与开发约定

更新日期：2026-10-23。项目采用一个仓库管理 Java 后端、Python RAG 和 Vue 前端；业务项目集中在 `project/`，开发环境集中在同级 `environment/`，本机运行数据留在既有私有区。

## 目录结构

```text
campus-rag-platform/               仓库根目录；日常命令默认从这里执行
├── README.md                      仓库导航与操作入口
├── project/                       业务项目与团队开发资料
│   ├── README.md                  业务开发入口
│   ├── pom.xml                    Java 17 聚合构建入口
│   ├── backend/                   六个 Java 服务
│   │   ├── gateway-service/       网关、认证入口与路由
│   │   ├── auth-service/          用户、角色与权限
│   │   ├── doc-service/           文档、版本与处理任务
│   │   ├── search-service/        检索与 Java/Python 协作
│   │   ├── admin-service/         管理功能
│   │   └── eval-service/          评测任务与结果
│   ├── frontend/                  Vue 页面、组件与 API 调用
│   ├── rag-runtime/               Python 检索、重排、生成、编排与 MCP
│   ├── database/                  MySQL 迁移、开发样例与 ES 索引定义
│   ├── deploy/                    业务 Docker、Nginx 与 Kubernetes 部署
│   ├── tests/                     跨模块 integration、e2e 与 fixtures
│   └── docs/                      团队接入、开发约定、接口与架构
├── environment/                   环境配置、安装、自检与日常启动入口
│   ├── README.md                  环境操作入口
│   ├── *.cmd                      项目共用的启动、停止与检查入口
│   ├── *.ps1、*.py                依赖、服务与模型管理及验证
│   ├── docker-compose.yml         开发中间件
│   ├── elasticsearch/、rocketmq/  中间件附属配置
│   ├── requirements-*             Python SDK 与模型依赖锁
│   ├── model-env.example          无密钥模型参数
│   ├── docs/                      详细安装、自检指南正文与原始参考手册
│   └── output/pdf/                可分发的详细安装与配置指南 PDF
├── .local/                        本机工具、模型、Docker 配置与数据
├── .venv/                         本机 Python 虚拟环境
└── .setup/                        本机运行状态、日志与检查记录
```

`.editorconfig`、`.gitattributes`、`.gitignore` 留在仓库根目录，分别维护缩进、换行和提交排除规则；`.git/` 由 Git 管理。根目录不再放业务 POM，Java 构建应显式选择 `project/pom.xml`。

`environment/` 维护开发环境，`project/deploy/` 维护业务应用部署；环境和模型检查留在 `environment/`，业务验证按模块范围放入模块自身测试目录或 `project/tests/`。无需复制同一份配置到多个目录。

Git 不保存空目录，尚无实现的位置使用 `.gitkeep` 保留；新增真实文件后可以删除对应占位。当前仍为目录骨架，目录名称不代表功能已经实现。

## 本机私有区与分享边界

下表位置也相对于仓库根目录。

| 本机位置 | 保存内容与处理方式 |
| --- | --- |
| `.local/DockerDesktop/`、`.local/Python311/`、`.local/Ollama/`、`.local/GitHubCLI/` | 已安装工具，保持原路径 |
| `.local/docker-profile/`、`.local/docker-cli/`、`.local/docker-data/` | Docker 配置、授权状态及数据盘，不分发 |
| `.local/models/`、`.local/ollama-models/` | 模型权重，成员按需自行下载 |
| `.venv/` | 本机 Python 环境，成员自行创建 |
| `.setup/state/`、`.setup/logs/` | 运行状态、备份和检查记录，仅本机保留 |
| `environment/.env`、`environment/.env.application` | 随机凭据和连接参数，与相应数据卷配套保管 |

这些运行目录保持既有位置，以保持现有工具、虚拟环境、Docker 数据盘及模型使用既有绝对路径。它们已被 Git 排除，实际内容保留。负责人专用启动包装、账号登录辅助、个人编辑器配置及自动化助手约定同样只留本机，不作为团队必需文件提交。

通过 Git 分享源码、项目共用环境脚本、模板、依赖锁和说明；不打包个人授权、本机辅助文件、运行区、安装包、数据卷、真实凭据或模型给队员。当前各成员使用独立本地数据库，通过版本化迁移和可公开样例共享结构与数据约定。

## Java、Python 与前端约定

`project/pom.xml` 管理 Java 17 和其下 `backend/` 的六个模块，各子模块的父 POM 路径仍为 `../../pom.xml`。模块 `artifactId` 和 `cn.campus.rag` 包名前缀保持一致；Maven 标准源码结构见[后端导航](../../backend/README.md)。在**仓库根目录**的开发终端执行：

```powershell
mvn.cmd -f .\project\pom.xml -o -B validate
mvn.cmd -f .\project\pom.xml -o -B -pl backend/doc-service -am validate
```

`-pl backend/doc-service` 相对于 `project/pom.xml` 所在目录。也可以先进入 `project/` 再执行普通 `mvn.cmd -o -B validate`；环境脚本仍应返回仓库根目录执行，避免混淆命令基准。

上述命令只校验模块结构。当前没有 Java 启动类与业务依赖，Spring Boot、Spring Cloud 与 Alibaba 版本须先统一，再写入 POM。不要沿用原始手册中尚未匹配的版本组合。

Python 使用仓库根目录独立 `.venv` 和 `environment/` 的锁文件，[project/rag-runtime/requirements.txt](../../rag-runtime/requirements.txt)通过 `../../environment/requirements-rag.lock.txt` 引用统一 SDK 依赖，不另维护一份版本。模型参数约定见 [model-env.example](../../../environment/model-env.example)，BGE large 向量维度为 **1024**。

前端尚无 `package.json` 与应用入口，需先统一工具链并提交包锁文件，再按实际脚本安装、启动和构建。当前没有可用的业务启动命令。

## 协作与维护

按[队员接入手册](../team/团队协作与接入.md)准备环境；有写入权限者使用任务分支，无写入权限者通过个人 Fork 提交 Pull Request。接口、表结构、索引、依赖版本或环境变量发生变更时，同步维护对应说明，经审查后合并。

2026-10-23 整理后，业务目录和聚合 POM 统一位于 `project/`；环境脚本、安装手册及指南 PDF 统一位于 `environment/`。文档总入口为 [project/docs/README.md](../README.md)，业务入口为 [project/README.md](../../README.md)。`environment/` 启动入口和所有本机运行区位置保持一致；旧检查日志中的历史路径保留原样，不作为当前操作入口。
