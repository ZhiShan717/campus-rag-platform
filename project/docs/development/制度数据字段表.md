# 制度数据字段表（戴月 · 10.24 / 10.25 交付）

更新日期：2026-10-25
适用范围：首轮 Demo「奖助学金制度查询」
配套数据：`project/database/mysql/seeds/demo-policies/`

本表是 Java 实体、MySQL 建表、Python 检索三方的共同契约。字段名一经冻结，改动需同步本文件、建表脚本和 `qa-cases.json`。

---

## 1. 三张表的关系

```text
documents（一份制度）
   └── document_versions（该制度的各个版本，1:N）
          └── chunks（版本切分后的条款，1:N）
```

检索时先按 `document_versions` 过滤出**当前有效**的版本，再只在有效版本的 `chunks` 里做匹配。这样「新版替代旧版」「废止不再引用」「未生效不能提前用」三件事都落在版本层，不需要在检索代码里写日期判断。

## 2. documents（制度主表）

| 字段 | 类型 | 必填 | 说明 | 值边界 |
| --- | --- | --- | --- | --- |
| `id` | VARCHAR(16) | 是 | 主键，`d001` 形式 | `^d\d{3}$` |
| `title` | VARCHAR(120) | 是 | 制度全称 | 10—120 字，不含书名号 |
| `doc_no` | VARCHAR(60) | 否 | 发文文号 | 如 `校学字〔2024〕12号`；虚构数据写 `〔演示〕` |
| `issuer` | VARCHAR(80) | 是 | 发布单位 | 校学生工作处 / 教育部 等 |
| `category` | VARCHAR(32) | 是 | 类别 | 枚举见下 |
| `source_type` | VARCHAR(16) | 是 | 数据来源性质 | `PUBLIC` / `FAKE_DEMO` |
| `source_note` | VARCHAR(255) | 是 | 来源说明或虚构声明 | `PUBLIC` 填公开文件出处；`FAKE_DEMO` 固定以「虚构演示数据」开头 |
| `created_at` | DATETIME | 是 | 入库时间 | ISO 8601 |

`category` 枚举：`NATIONAL_SCHOLARSHIP`（国家奖学金）、`NATIONAL_GRANT`（国家助学金）、`NATIONAL_INSPIRATION`（国家励志奖学金）、`SCHOOL_SCHOLARSHIP`（校级奖学金）、`NEED_ASSESSMENT`（困难认定）、`WORK_STUDY`（勤工助学）、`STUDENT_LOAN`（助学贷款）。

> 演示数据里除「国家奖学金评审办法」按公开文件精神虚构改写外，其余均为 `FAKE_DEMO`。前端和报告必须能区分两者，不能把虚构条款说成真实规定。

## 3. document_versions（版本表）

| 字段 | 类型 | 必填 | 说明 | 值边界 |
| --- | --- | --- | --- | --- |
| `id` | VARCHAR(16) | 是 | 主键，`v001` 形式 | `^v\d{3}$` |
| `document_id` | VARCHAR(16) | 是 | 外键 → documents.id | 必须存在 |
| `version_no` | VARCHAR(32) | 是 | 版本标识 | `2021版`、`2024修订` 等 |
| `status` | VARCHAR(16) | 是 | 版本状态 | `ACTIVE` / `SUPERSEDED` / `ABOLISHED` / `PENDING` |
| `effective_date` | DATE | 是 | 生效日期 | `YYYY-MM-DD` |
| `expiry_date` | DATE | 否 | 失效日期，无则 NULL | 必须 ≥ effective_date |
| `replaced_by` | VARCHAR(16) | 否 | 被哪一版替代 | 指向同 `document_id` 下的其他版本 |
| `published_date` | DATE | 是 | 发布日期 | ≤ effective_date |
| `summary` | VARCHAR(255) | 否 | 本版变更摘要 | 变更点一句话 |

### 状态语义（检索过滤规则）

| status | 含义 | 进入默认检索 | 进入历史浏览 |
| --- | --- | --- | --- |
| `ACTIVE` | 当前有效 | 是 | 是 |
| `SUPERSEDED` | 已被新版替代 | 否 | 是 |
| `ABOLISHED` | 已废止 | 否 | 是（标注废止） |
| `PENDING` | 已发布、未到生效日 | 否 | 是（标注未生效） |

约束：

1. 同一 `document_id` 下最多一个 `ACTIVE`。
2. `status = SUPERSEDED` 必须填 `replaced_by`；被指向的版本必须存在且不是它自己。
3. `status = ABOLISHED` 必须有 `expiry_date`。
4. `status = PENDING` 的 `effective_date` 必须晚于数据整理日（本数据集为 2026-09-01）。
5. `replaced_by` 只能指向同 `document_id` 的版本，不允许跨制度。

## 4. chunks（条款表）

| 字段 | 类型 | 必填 | 说明 | 值边界 |
| --- | --- | --- | --- | --- |
| `id` | VARCHAR(16) | 是 | 主键，`c001` 形式 | `^c\d{3,4}$`，全局唯一 |
| `version_id` | VARCHAR(16) | 是 | 外键 → document_versions.id | 必须存在 |
| `clause_no` | VARCHAR(32) | 是 | 条款序号 | `第一条`…`第三十条` |
| `section_path` | VARCHAR(160) | 是 | 所属章节路径 | `第二章 申请条件` 或 `四、评审程序` |
| `order_no` | INT | 是 | 在本文档内的排序 | 从 1 连续递增 |
| `content` | TEXT | 是 | 条款原文 | 20—500 字，一句一事 |

字段值边界（针对检索质量）：

- `content` 必须自带主体（谁、做什么）与条件（满足什么），不要写「同上」「见前条」。
- 金额统一写阿拉伯数字加「元」，不写「两千元」。
- 百分比统一写「前 10%」这种形式，不写「10％」（全角）以免分词异常。
- 日期写「2024 年 9 月 1 日」，不写「2024.9.1」。

## 5. 与测试集的对应

`project/tests/fixtures/qa-cases.json` 每题包含：

| 字段 | 说明 |
| --- | --- |
| `id` | `q01` 形式 |
| `question` | 用户提问原文 |
| `type` | `NORMAL` / `VERSION` / `INVALID` / `NO_EVIDENCE` |
| `expected_chunk_ids` | 期望命中的条款；`NO_EVIDENCE` 类为空数组 |
| `excluded_chunk_ids` | 必须不出现的条款（旧版、废止、未生效） |
| `expected_mode` | `CLAUSE_RETRIEVAL` 或 `NO_EVIDENCE` |
| `note` | 判定理由，给人看的部分 |

判定口径：命中集合必须包含全部 `expected_chunk_ids`，且与 `excluded_chunk_ids` 无交集；`NO_EVIDENCE` 类必须返回空结果且页面标注「无依据」，不得回退成网络错误。
