# Infrastructure version sources

Checked on 2026-10-22. These files configure independent local development services only.

- Elasticsearch and IK are both fixed at **8.11.4**. The [IK maintainer's installation instructions](https://github.com/infinilabs/analysis-ik#how-to-install) require the plugin version to match Elasticsearch exactly. The Dockerfile installs from the maintainer's `get.infini.cloud` endpoint; its 8.11.4 URL returned HTTP 200 during setup.
- **MinIO RELEASE.2024-12-18T13-15-44Z** is delivered through the OpenEBS mirror. The original DockerHub repository returned 404 and the original binary/checksum archives returned 410. [OpenEBS issue 4332](https://github.com/openebs/openebs/issues/4332) and [merged PR 4337](https://github.com/openebs/openebs/pull/4337) document the same migration to `openebs/minio`. Compose pins the mirror's multi-platform index digest `sha256:bb04e41fc1b876c5f752ea3c5957a73db73a1fb7df49ce6bb95f722f0abfb1ba`, verified through DockerHub's tag API. This is the OpenEBS mirror of the upstream release, not an image published by MinIO.
- **Nacos 2.3.2** uses [the official versioned Docker configuration](https://github.com/nacos-group/nacos-docker/tree/v2.3.2). Its [authentication guide](https://nacos.io/en/docs/v2.3/guide/user/auth/) requires a deployment-specific token secret and server identity. The initializer generates a Base64 token from 48 random bytes. `Start-Services.ps1` replaces the original administrator password through [the 2.3.2 user API](https://github.com/alibaba/nacos/blob/2.3.2/plugin-default-impl/nacos-default-auth-plugin/src/main/java/com/alibaba/nacos/plugin/auth/impl/controller/UserController.java) and verifies the generated password. Embedded Derby persists independently of the `campus_rag` MySQL database.
- **RocketMQ 5.3.1** is optional under the `messaging` profile. The [official Docker Compose guide](https://rocketmq.apache.org/docs/quickStart/03quickstartWithDockercompose/) supplies the service layout. The versioned [runbroker.sh](https://github.com/apache/rocketmq/blob/rocketmq-all-5.3.1/distribution/bin/runbroker.sh) appends `JAVA_OPT_EXT` after its large default memory settings; the development values therefore take precedence. The [versioned store configuration](https://github.com/apache/rocketmq/blob/rocketmq-all-5.3.1/store/src/main/java/org/apache/rocketmq/store/config/MessageStoreConfig.java) uses `mappedFileSizeCommitLog` for the smaller 64 MiB development segment. The advertised broker address is intended for local Windows clients on `127.0.0.1`, not clients in other containers.
- MySQL uses the [official MySQL 8.0 image](https://hub.docker.com/_/mysql) and its standard empty-volume database/user initialization. Redis uses the [official Redis image](https://hub.docker.com/_/redis), fixed at `7.4.2-alpine`.

During local verification, the RocketMQ image ran as uid/gid `3000:3000`, but the newly created named-volume mount points were owned by `root:root`. The `rocketmq-volume-init` service therefore sets ownership of only the three message-service mount-point directories before the non-root Java services start. It has no network access and exits after initialization; it neither runs the broker as root nor removes persistent data. The message-service verification checks the actual `mqadmin clusterList` registration as well as container health.

`Start-Services.ps1` and `Stop-Services.ps1` always supply explicit project-directory, environment-file, Compose-file, and project-name arguments, so they work from another current directory. Use quiet Compose validation to avoid printing expanded credentials. Keep the protected `.env` with the persistent named volumes; changing the file alone does not rotate passwords already stored by MySQL, Elasticsearch, or Nacos.
